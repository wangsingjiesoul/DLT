# ADR-0001：使用 PushPlus 统一接入微信和 QQ 通知

## 状态

已接受

## 背景

部署后的服务需要向用户发送下一期大乐透候选号码。直接对接个人微信没有公开稳定的机器人接口；QQ 官方机器人需要单独创建机器人并处理鉴权、主动消息限制和审核。项目需要低门槛、可由环境变量配置、适合个人部署的通知方式。

## 决策

使用 PushPlus 消息接口作为首个通知适配器。默认渠道为 `wechat`，也允许把 `PUSHPLUS_CHANNEL` 改为 `qq`。项目只保存 Token 的环境变量名，不保存真实 Token。

## 结果

### 正面

- 同一套接口覆盖微信和 QQ。
- 只需要一个 Token，部署步骤少。
- 支持 Markdown，号码消息可读性较好。
- 后续可以增加企业微信 Webhook 等其他适配器，而不修改预测逻辑。

### 负面

- 依赖第三方服务可用性和服务条款。
- 接口成功只代表消息被服务端接收，最终投递是异步过程。
- 用户需要在 PushPlus 完成账号和渠道配置。

## 备选方案

- 企业微信群机器人：官方且简单，但只能发到企业微信群，不是普通个人微信。
- QQ 官方机器人：控制力强，但申请、鉴权和主动消息限制更复杂。
- NapCat/OneBot：部署灵活，但依赖非官方客户端，存在账号风控风险。
