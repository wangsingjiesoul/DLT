# ADR-0004：使用外部 AI 模型重排统计候选

## 状态

已接受

## 背景

原预测器是确定性的统计集成模型，能够基于频率、指数衰减、遗漏和号码结构生成三组候选，但并未调用外部 AI。项目需要支持真实 AI 模型调用，同时不能允许不可控的模型输出绕过号码校验，也不能在模型服务失败时悄悄伪装成 AI 结果。

## 决策

采用两阶段架构：统计预测器先为均衡、趋势、探索三种策略生成带稳定 ID 的合法候选池；OpenAI-compatible 模型只负责从每种策略的候选池中选择一个 ID，并返回简短理由。本地程序对 JSON 结构、策略集合、候选归属、重复选择和最终号码合法性进行完整校验。

运行时提供两种失败策略：

- `AI_REQUIRED=false`：AI 失败后使用原统计结果，并公开记录回退原因。
- `AI_REQUIRED=true`：AI 失败后终止预测，因此自动通知也不会发送。

历史回测不调用外部 AI，只评估确定性的统计候选层。

## 结果

### 正面

- 项目确实调用外部模型，同时最终号码始终受本地规则约束。
- 模型供应商可通过兼容接口地址和模型名替换。
- 失败状态透明，严格模式可以确保消息必定经过 AI。
- 回测保持低成本、可复现且不存在外部模型版本漂移。

### 负面

- AI 调用增加延迟、费用和第三方依赖。
- 模型重排本身不可证明能提高随机开奖的中奖概率。
- 同一模型也可能随供应商版本变化给出不同选择。

## 备选方案

- 让 AI 直接生成号码：输出自由但不可控，容易违反约束，也难以解释和测试。
- 只保留统计模型并改名为 AI：实现简单但不满足真实模型调用要求。
- 在全部历史回测中调用 AI：理论上能测试整体流程，但费用高、不可复现，并可能因上下文设计引入未来信息。
