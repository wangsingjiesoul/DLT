# AI 模型重排实施计划

## 目标

在现有可复现统计预测之上接入 OpenAI-compatible 外部模型。统计层负责生成和评分合法候选池，AI 只能按候选 ID 为均衡、趋势、探索三种策略各选择一组并给出简短理由。所有 AI 输出都必须经过本地验证后才能保存、展示或发送。

## 安全与产品边界

- API Key 只从 `AI_API_KEY` 环境变量读取，不写入仓库、日志、网页或预测文件。
- 请求设置超时和最大响应体限制；错误信息不得包含请求头、完整请求体或密钥。
- AI 不直接创造号码，不能绕过大乐透号码范围、数量、去重和候选池约束。
- `AI_REQUIRED=true` 时调用或校验失败会终止本次预测与通知。
- `AI_REQUIRED=false` 时失败会回退统计选择，并在结果中明确记录回退状态和安全错误原因。
- AI 重排不宣称、也不能证明提高中奖概率。
- 历史回测默认不调用外部 AI，以控制费用并保持可复现、避免测试数据污染。

## 实施步骤

1. 新增 `dlt/ai.py`
   - 定义 AI 配置、可安全展示的元数据和模型调用异常。
   - 使用标准库调用 OpenAI-compatible `chat/completions` 接口。
   - 要求 JSON 输出，解析模型返回并验证基础结构。
   - 限制 URL 协议、超时和响应体大小，屏蔽敏感错误信息。

2. 扩展 `dlt/predictor.py`
   - 为三种策略各构建一组带稳定 ID 的候选摘要。
   - 在无 AI 时保持原有确定性统计结果。
   - AI 启用时提交候选池，验证每种策略恰好选择一个属于该策略的候选 ID。
   - 对最终号码再次执行数量、范围、排序、去重和跨策略重复校验。
   - 在预测结果中加入 `ai` 元数据以及每组的 AI 理由。

3. 串接运行入口
   - `main.py` 从环境变量构建 AI 选择器，并注入 CLI、自动任务和 Web 服务。
   - 自动任务复用同一个预测函数；严格模式失败时不得发送通知。
   - Web 缓存只有在数据期号和当前 AI 配置标识一致时才复用。

4. 更新界面和通知
   - 页面展示 AI 是否启用、是否真正参与、模型名和回退状态。
   - 页面展示每组 AI 选择理由；没有 AI 时继续展示统计说明。
   - 微信/QQ 消息标明 AI 参与或统计回退，避免误导。

5. 更新配置和部署文档
   - `.env.example`、`compose.yaml` 增加 `AI_ENABLED`、`AI_REQUIRED`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`AI_TIMEOUT`。
   - README 说明兼容接口配置、严格/回退行为、费用和隐私边界。
   - 架构文档加入 AI 重排层和故障处理。

6. 验证
   - 测试成功响应、无效 JSON、非法候选 ID、超时/网络错误、严格模式、回退模式和密钥不泄漏。
   - 回归预测、自动任务、通知和 Web 测试。
   - 运行 `python -m unittest discover -s tests -v`。
   - 运行 `docker compose config` 检查部署变量。

7. 全项目自检、注释和零基础文档
   - 检查全部 Python、HTML、JavaScript、CSS、Docker 与 Compose 文件，修复影响可靠性、安全性或可读性的明确问题。
   - 为模块、类、函数、关键分支和外部接口补充面向初学者的解释性注释；避免给每一行添加重复注释。
   - 为测试代码补充“这个测试保护什么行为”的说明，让初学者能从测试理解需求。
   - 新增 `docs/beginner-guide.md`，从 Python 基础、目录结构、数据流、AI 调用、通知、Web、测试、Docker 和常见故障逐步讲解。
   - 在 README 增加零基础学习入口和推荐阅读顺序。

## 完成标准

- 配置 AI 后，`predict`、`run-once`、定时任务及首次 Web 预测都会真实调用模型。
- 预测 JSON 和页面能够区分“AI 已选择”“AI 回退”“未启用 AI”。
- 严格模式下，AI 未成功参与就不生成新的通知。
- 任意模型输出都不能把候选池之外的号码送入最终结果。
- 所有自动化测试通过，示例配置不包含真实密钥。
- 代码中的关键概念均有中文注释，初学者可按文档独立完成本地运行、AI 配置、测试和部署。
