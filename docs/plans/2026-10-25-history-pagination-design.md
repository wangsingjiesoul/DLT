# 历史开奖分页页面设计

## 目标

在现有预测首页下方展示全部大乐透历史开奖记录，同时避免一次把近三千条数据传给浏览器。

## 方案比较

- 一次返回全部数据：实现最简单，但页面首次加载和 DOM 节点数量会持续增长。
- 浏览器拿全部数据后本地分页：翻页快，但仍然存在首次下载和内存问题。
- 服务端分页：每次只读取和返回当前页，数据继续增长时性能更稳定。本项目采用此方案。

## API

新增：

```text
GET /api/history?page=1&page_size=30
```

响应字段：`items`、`page`、`page_size`、`total`、`total_pages`。页码必须大于等于 1，每页必须在 1～100 条之间。保留原 `/api/history/latest`，兼容已有调用。

## 页面

- 默认每页 30 条，支持 20、30、50、100 条切换。
- 显示总期数、当前页、总页数、上一页、下一页和页码输入。
- 每行展示期号、日期、5 个前区红球和 2 个后区蓝球。
- 加载、空数据和请求失败均有明确状态。
- 桌面端使用紧凑表格，手机端允许表格横向滚动，不压缩号码球到不可读。
- 翻页后滚动到历史区顶部，不刷新整个页面，也不重新调用 AI 预测接口。

## 安全和性能

- 所有数据继续使用 `textContent` 创建，不把 API 内容作为 HTML 注入。
- 服务端限制 `page_size <= 100`。
- 历史数据只读，不增加公网修改或发送接口。
