# 大乐透推荐服务架构

## 需求

### 功能需求

- 只处理超级大乐透数据。
- 增量获取最新开奖结果并校验后写入 `data/dlt.json`。
- 基于历史数据生成均衡、趋势、探索三类候选组合。
- 提供网页和只读 JSON API 查看候选结果。
- 默认通过 Qmsg酱发送 QQ 消息，并保留 PushPlus 兼容适配器。
- 支持 Docker 部署、手动运行和内置定时运行。

### 非功能需求

- 单机低流量场景，避免数据库、消息队列等额外运维。
- 预测结果对同一期号可复现，自动发送按期号去重。
- 外部数据源或通知服务失败时保留现有数据和预测结果。
- Token/Webhook 只从环境变量读取，不进入日志、API 或 Git。
- 所有对外页面明确声明开奖结果具有随机性，模型评分不等于中奖概率。

## 高层架构

```text
500 历史开奖页面
        │
        ▼
增量更新器 ──校验/去重/原子写入──> data/dlt.json
                                      │
                                      ▼
                              预测与候选生成器
                                      │
                  ┌───────────────────┼───────────────────┐
                  ▼                   ▼                   ▼
          runtime/prediction.json   Web/API          通知适配器
                                                        │
                                      ┌─────────────────┴────────────────┐
                                      ▼                                  ▼
                               Qmsg酱（默认）                    PushPlus（兼容）
                                      │                                  │
                                      QQ                              微信或 QQ
```

## 组件

- `dlt/data.py`：数据加载、字段及号码范围校验、原子 JSON 写入。
- `dlt/updater.py`：抓取并解析大乐透历史表格，增量合并。
- `dlt/predictor.py`：滚动统计、走步友好的特征计算和多样化候选生成。
- `dlt/notifier.py`：构造通知消息并调用 Qmsg酱或 PushPlus。
- `dlt/automation.py`：执行“更新 → 预测 → 按期号去重发送”的完整周期。
- `dlt/web.py`：网页、健康检查和只读 API。
- `main.py`：命令行入口及定时调度。

## 故障处理

| 故障 | 行为 |
|---|---|
| 数据源超时或解析失败 | 不覆盖本地数据，记录错误，仍可读取已有预测 |
| 新数据校验失败 | 拒绝写入整个更新批次 |
| 通知服务返回错误 | 保留预测结果，不更新已发送期号，允许重试 |
| 服务重启 | 从 `runtime/` 恢复最近预测和通知状态 |
| 同一分钟重复触发 | 使用本地调度状态和目标期号双重去重 |

## 安全边界

- 服务只公开 GET/HEAD；生成和通知操作只通过本机 CLI 或调度器执行。
- 静态文件路径必须解析在 `web/` 目录内，阻止路径穿越。
- HTTP 响应包含 CSP、`nosniff`、禁止 iframe 等安全头。
- 外部 HTTP 请求设置超时、固定目标域名并限制响应大小。
