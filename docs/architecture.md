# 大乐透推荐服务架构

## 需求

### 功能需求

- 只处理超级大乐透数据。
- 增量获取最新开奖结果并校验后写入 `data/dlt.json`。
- 基于 30/100/300 期号码特征和最多 1,000 期经验结构分布生成三类候选组合。
- 可调用 OpenAI-compatible 外部模型，从本地合法候选 ID 中进行受控重排。
- 提供网页和只读 JSON API 查看候选结果。
- 默认通过 Qmsg酱发送 QQ 消息，并保留 PushPlus 兼容适配器。
- 支持 Docker 部署、手动运行和内置定时运行。

### 非功能需求

- 单机低流量场景，避免数据库、消息队列等额外运维。
- 预测结果对同一期号可复现，自动发送按“期号 + 渠道”去重。
- 外部数据源、AI 或通知服务失败时，不破坏现有数据和已保存结果。
- Token、Webhook 和 AI API Key 只从环境变量读取，不进入日志、API、镜像或 Git。
- 所有对外页面明确声明开奖结果具有随机性，统计评分和 AI 重排不等于中奖概率。

## 高层架构

```text
500 历史开奖页面
        │
        ▼
增量更新器 ──校验/去重/原子写入──> data/dlt.json
                                      │
                                      ▼
                  统计特征、经验结构与合法候选池
                                      │
                           ┌──────────┴──────────┐
                           │                     │
                           ▼                     ▼
                    统计回退选择       OpenAI-compatible AI
                           │              只返回候选 ID
                           └──────────┬──────────┘
                                      ▼
                              本地结构与 ID 复核
                                      │
                  ┌───────────────────┼───────────────────┐
                  ▼                   ▼                   ▼
          runtime/prediction.json   Web/API          通知适配器
                                                        │
                                      ┌─────────────────┴────────────────┐
                                      ▼                                  ▼
                               Qmsg酱（默认）                    PushPlus（兼容）
                                      │                                  │
                                      QQ                              微信或 QQ
```

## 组件

- `dlt/data.py`：数据加载、字段及号码范围校验、原子 JSON 写入。
- `dlt/updater.py`：抓取并解析大乐透历史表格，增量合并。
- `dlt/predictor.py`：滚动统计、历史结构校准、候选池、AI 选择约束和多样化结果生成。
- `dlt/backtest.py`：只使用过去数据的滚动回测、重复随机基线和配对置信区间。
- `dlt/ai.py`：OpenAI-compatible 请求、超时、响应大小限制和安全 JSON 解析。
- `dlt/notifier.py`：构造通知消息并调用 Qmsg酱或 PushPlus。
- `dlt/automation.py`：执行“更新 → 预测 → 按期号去重发送”的完整周期。
- `dlt/web.py`：网页、健康检查、预测 API 和历史分页 API。
- `main.py`：命令行入口及定时调度。

## 故障处理

| 故障 | 行为 |
|---|---|
| 数据源超时或解析失败 | 不覆盖本地数据，记录错误，仍可读取已有预测 |
| 新数据校验失败 | 拒绝写入整个更新批次 |
| AI 超时、HTTP 错误或无效 JSON | 严格模式终止预测；回退模式明确标记后使用统计选择 |
| AI 返回候选池外 ID 或重复策略 | 本地拒绝该响应，不允许模型直接号码进入结果 |
| Web 首次并发请求 | 进程内生成锁确保同一缓存缺失只调用一次 AI |
| Web 缓存为 AI 回退结果 | 10 分钟内复用以限制费用，冷却后自动再次尝试 AI |
| 通知服务返回错误 | 保留预测结果，不更新已发送期号，允许重试 |
| 服务重启 | 从 `runtime/` 恢复最近预测和通知状态 |
| 同一分钟重复触发 | 使用本地调度状态、目标期号和渠道标识去重 |
| 部分通知渠道失败 | 成功渠道立即落盘，后续只重试失败渠道 |
| Windows 缺少 IANA 时区库 | `Asia/Shanghai` 安全退回当前适用的固定 UTC+8；Docker 仍安装完整 tzdata |

## 模型证据边界

- 所有合法单注的理论中奖概率相同；频率、遗漏和结构分只用于候选排序与覆盖设计。
- AI 不读取密钥，也不直接读取整份历史 JSON；后端先把历史压缩成可复现的特征、结构摘要和合法候选。
- AI 只能返回候选 ID。它的作用是多指标比较和生成简短解释，不被描述为预测概率来源。
- 回测按时间滚动，目标期开奖永远不会出现在对应训练数据里。
- 随机基线会重复抽样，输出配对均值差与近似 95% 置信区间。区间跨 0 时结果必须标记为证据不足。
- 参数仍可能受同一历史数据影响，因此历史回测即使领先，也需要后续真实开奖的样本外验证。

## 安全边界

- 服务只公开 GET/HEAD；生成和通知操作只通过本机 CLI 或调度器执行。
- 静态文件路径必须解析在 `web/` 目录内，阻止路径穿越。
- HTTP 响应包含 CSP、`nosniff`、禁止 iframe 等安全头。
- 外部 HTTP 请求设置超时并限制响应大小；数据源和通知地址固定在代码中。
- AI Base URL 只能由部署者通过环境变量配置，不能由 Web 请求指定；URL 不允许携带账号、密码、查询参数或锚点。
- 模型文本通过 `textContent` 展示，Markdown 通知会转义控制符，避免把模型输出当作可执行 HTML。
- `.dockerignore` 排除 `.env`，防止本机密钥被 `COPY . /app` 打进镜像。
